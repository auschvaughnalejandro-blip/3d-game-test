# One Valley

A Unity 6 URP action-RPG vertical slice. Five rounds in a valley, then a three-phase
boss fight against the Warden.

## Getting this running on a new machine

You need **Unity 6000.5.9f1** (exactly — through Unity Hub) and **git-lfs**. Blender
4.5 LTS is optional, and only needed to regenerate the art.

```bash
git lfs install                 # BEFORE cloning, or binaries arrive as text stubs
git clone https://github.com/auschvaughnalejandro-blip/3d-game-test.git
cd 3d-game-test
python Tools/setup_new_machine.py
```

`setup_new_machine.py` does the three things git cannot carry across machines: installs
the LFS filters, registers Unity's YAML merge driver against your Unity install, and
clears the read-only bit from any older checkout. It is safe to run repeatedly.

Then open the folder in Unity Hub. The first import takes a while — `Library/` is
deliberately not committed and gets rebuilt from scratch.

## Layout

| Path | What it is |
| --- | --- |
| `Assets/Scripts/` | All gameplay code. This is exactly `Assembly-CSharp`. |
| `Assets/Editor/` | Editor-only tools. A **separate** assembly. |
| `Assets/Scenes/SampleScene.unity` | The only scene. |
| `Tools/` | Python that generates the art. See below. |
| `Docs/` | Design docs — asset bible, story plan, pathfinding maths. |
| `CLAUDE.md` | The hard-won rules. Read this before changing anything. |

## The art is code

Every character, weapon and prop is generated by Python, not sculpted by hand. The FBX
files in `Assets/Resources/Models/` are **outputs**; `Tools/build_*.py` are the source.
`ov_kit.py` and `ov_character_kit.py` are the shared libraries.

Two ways to run a build, both of which work on any machine:

```bash
# headless — no Blender window needed
blender --background --python Tools/build_weapons.py

# or into an already-open Blender, through the addon's socket
python Tools/blender_send.py Tools/build_weapons.py
```

Neither hardcodes a path. `blender_send.py` injects `ONEVALLEY_ROOT` before shipping the
script; a direct `--background --python` run resolves the root from the file's own
location.

Note that FBX exports embed a timestamp, so a rebuild always produces different bytes
even when the geometry is identical. Don't read a diff there as a change.

## Testing

**One Valley → Run Self Test** in the Unity menu bar plays all five rounds, walks into
the portal, fights the Warden through its three phases, and writes `selftest.log` plus a
`selftest_done.txt` marker into `Logs/`. It takes about 35 seconds.

To check that C# compiles without opening Unity at all, see the "Compile-checking
without Unity" section of `CLAUDE.md` — it drives the Roslyn compiler that ships inside
the Unity install.

## Working from another device

`Tools/remote_preflight.py` checks that Blender, the Unity bridge and the repo are all in
a state that can be driven remotely, and prints GO or NO-GO. The "Working from another
device" section of `CLAUDE.md` explains the setup and its one hard constraint: the host
machine has to stay awake, because neither Blender's addon nor Unity's bridge has a
headless server mode.
